- 输出约定

## 输出约定

完成镜像诊断后，始终输出：

1. Findings
2. Shrink options
3. Tradeoffs
4. Next fix to implement

建议必须基于证据。不要在没有证据支撑的前提下给出泛化清理建议。

## 证据到建议的映射

### apt 层很大

证据：

- `docker history` 里存在很大的 `RUN apt-get ...` 层
- `/var/lib/apt/lists` 或 `/var/cache/apt` 等缓存目录非零

建议：

- 在同一个 `RUN` 层里清理 apt 索引
- 除非有明确的安全或兼容性理由，否则避免 `apt-get upgrade -y`
- 删除不必要的系统包
- 如果这是运行时镜像，把构建依赖移动到 builder 阶段

### 全局 npm 安装层很大

证据：

- 存在很大的 `RUN npm install -g ...` 层
- `/usr/local/lib/node_modules` 很大
- `/root/.npm` 非零

建议：

- 在同一层里清理 npm 缓存
- 删除或改成可选安装的大型全局 CLI
- 减少最终镜像里的全局 npm 包数量
- 如果这是运行时镜像，把开发类 CLI 移出最终阶段

### 从 builder 镜像复制了很大的 `/usr/local`

证据：

- `docker history` 里出现 `COPY --from=... /usr/local/ /usr/local/`
- `/usr/local` 是主要体积来源

建议：

- 只复制必需的二进制或子目录，而不是整棵目录树
- 在合适场景下优先考虑官方的 slim 运行时镜像
- 避免把头文件、文档、包管理器等无关内容一并复制进来

### Go 工具链很大

证据：

- 存在 `COPY --from=golang ... /usr/local/go`
- `/usr/local/go` 很大
- `/usr/local/go/pkg` 非零

建议：

- 如果这是运行时镜像，把 Go 保留在 builder 阶段，不带入最终镜像
- 如果这是开发镜像，可以保留 Go，但应评估是否还需要同时保留构建缓存
- 清理最终镜像里不需要的 Go 包缓存或构建缓存

### 缓存目录非零

证据：

- `/root/.cache`
- `/root/.npm`
- `/root/.cargo`
- `/root/go`
- `/var/lib/apt/lists`
- `/var/cache/apt`

建议：

- 在产生这些缓存的同一个 `RUN` 层里清理它们
- 检查清理条件是否写反、是否被错误分支挡住
- 尽量使用不会留下大体积缓存的确定性安装命令

## 风险分层

### 低风险

- 清理包管理器缓存
- 收窄过于宽泛的 `COPY`
- 删除明显无用的诊断或便捷包

### 中风险

- 从开发镜像里移除全局 CLI
- 去掉 `apt-get upgrade -y`
- 将完整运行时镜像替换为 slim 基础镜像

### 高风险

- 在未确认镜像用途前移除语言运行时或工具链
- 从开发容器中剥离交互式使用仍然需要的包
- 激进删除运行时可能仍然依赖的缓存或目录

## 不同镜像类型的判断启发

- 开发容器：默认认为部分运行时和工具链体积是有意负载，优先优化缓存和冗余包。
- 运行时镜像：强烈优先考虑多阶段构建和更窄的最终文件系统。
- CI 镜像：保留流水线所需工具，但仍然要清缓存并避免不必要的宽泛复制。

如果判断不确定，明确说出你当前的假设，以及假设错误时建议会如何变化。
