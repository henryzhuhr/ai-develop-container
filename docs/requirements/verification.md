# 验证与验收需求

总入口见 [requirements.md](../requirements.md)。

## 1. 背景

当前仓库尚未建立正式自动化测试套件，但需求已经要求该镜像具备多语言和 AI CLI 的开箱即用能力，因此需要建立基础验证标准。

## 2. 目标

- 让镜像构建结果具备最小可验证性。
- 用统一命令覆盖多语言工具链与主要 AI CLI。
- 为后续 CI 验证扩展提供基线。

## 3. 非目标

- 第一阶段不要求完整自动化测试矩阵。
- 第一阶段不要求覆盖所有语言生态工具。

## 4. 需求项

### 4.1 构建验证

- `VF-001` 至少应验证 `bash scripts/docker-build.sh` 可成功执行。

### 4.2 冒烟验证

- `VF-002` 至少覆盖 `node -v`。
- `VF-003` 至少覆盖 `go version`。
- `VF-004` 至少覆盖 `python3 --version`。
- `VF-005` 至少覆盖 `uv --version`。
- `VF-006` 至少覆盖 `java -version`。
- `VF-007` 至少覆盖 `javac -version`。
- `VF-008` 至少覆盖 `claude --version` 或等价检查方式。
- `VF-009` 至少覆盖 `codex --version` 或等价检查方式。

### 4.3 运行验证

- `VF-010` 应验证容器启动后挂载项目目录和工作目录行为正常。

## 5. 验收标准

- 有明确的构建验证命令。
- 有明确的运行和冒烟验证命令。
- 文档中能直接复用这些命令。

- 多语言冒烟验证：已完成。
- AI CLI 验证：已完成。
