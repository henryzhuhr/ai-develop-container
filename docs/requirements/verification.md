# 验证与验收需求

总入口见 [requirements.md](../requirements.md)。

## 1. 背景

当前仓库尚未建立正式自动化测试套件，但需求已经要求该镜像具备多语言和 AI CLI 的开箱即用能力，因此需要建立基础验证标准。

## 2. 目标

- 让镜像构建结果具备最小可验证性。
- 用统一命令覆盖多语言工具链与主要 AI CLI。
- 为后续 CI 验证扩展提供基线。

## 3. 非目标

- 第一阶段不要求完整自动化测试矩阵。
- 第一阶段不要求覆盖所有语言生态工具。

## 4. 需求项

### 4.1 构建验证

- 至少应验证 `bash scripts/docker-build.sh` 可成功执行。

### 4.2 冒烟验证

- 至少覆盖以下命令：
  - `node -v`
  - `go version`
  - `python3 --version`
  - `uv --version`
  - `java -version`
  - `javac -version`
  - `claude --version` 或等价检查方式
  - `codex --version` 或等价检查方式

### 4.3 运行验证

- 应验证容器启动后挂载项目目录和工作目录行为正常。

## 5. 验收标准

- 有明确的构建验证命令。
- 有明确的运行和冒烟验证命令。
- 文档中能直接复用这些命令。

## 6. 当前状态

- 构建验证：部分完成。
- 多语言冒烟验证：未完成。
- AI CLI 验证：未完成。

## 7. 待决策项

- 是否把验证纳入 CI。
